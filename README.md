# AAIT Sales Dashboard

لوحة داخلية لمتابعة اجتماعات فريق المبيعات والتنبيه قبل المواعيد، مبنية بـ Vite وJavaScript.

## التشغيل

```bash
npm ci
npm run dev
```

الاختبارات والبناء:

```bash
npm test
npm run build
```

## مصدر البيانات

- تقرأ نسخة Vercel التبويب الشهري تلقائيًا عبر `/api/meetings`.
- اسم التبويب يكون مثل `اغسطس 2026`.
- يمكن ضبط مفتاح النشر في Vercel عبر `GOOGLE_SHEETS_PUBLISH_KEY`.
- ترتيب الأعمدة: التاريخ، المشروع، الفريق، الوقت، نوع الاجتماع، الحالة، رابط التذكرة، رابط الاجتماع، حالة العميل.
- الأوقات الأحادية من `1:00` إلى `9:00` تُعامل كفترة مسائية حسب اتفاق الجدول الحالي. اكتب `08:00` أو أضف `ص` لتحديد وقت صباحي صراحةً.

## الاعتمادية

- تعرض اللوحة حالة المزامنة وآخر تحديث.
- تستخدم نسخة محلية مخزنة عند فشل المصدر، مع تحذير واضح عند تقادمها.
- التنبيهات المنفذة محفوظة يوميًا لمنع تكرارها بعد إعادة تحميل الصفحة.
- المنطقة الزمنية المعتمدة هي `Asia/Riyadh`.
- يعرض النظام تذكيرًا صوتيًا هادئًا مرة واحدة لكل صلاة في الرياض عند تفعيل الصوت من نفس الشاشة.

## مركز النداءات الداخلية

تتوفر لوحة منفصلة على `/control` ضمن المشروع نفسه. يستخدم مركز التحكم خط «ثمانية» (Thmanyah Sans) من ملفات WOFF2 التي وفرها مالك المشروع، وفق تأكيده بوجود موافقة شفهية على التضمين؛ ويظل الخط محصورًا في مركز التحكم وصفحة الدخول دون تغيير خط لوحة العرض الرئيسية. لوحة العرض هي مستقبِل فقط؛ حسابات المسؤولين لا تسجل الدخول إليها.

### الصلاحيات

- `general_manager`: نداء الحضور إلى المكتب فقط.
- `business_development_manager`: نداء المكتب أو اجتماع لأي موظف.
- `deputy_general_manager`: نداء المكتب أو اجتماع لأي موظف.

تسجيل الدخول بكلمة مرور فقط. يطابق الخادم كلمة المرور مع تجزئات منفصلة ومملحة للمسؤولين الثلاثة، ثم يصدر Firebase Custom Token إلى UID ثابت. تُراجع الصلاحية ورقم الجلسة على الخادم لكل نداء، ولا تُقبل الجلسات القديمة بعد تغيير كلمة المرور أو تسجيل الخروج. الموظفون الذين يمكن توجيه النداء لهم ثابتون في الواجهة: مجاهد، محمود، أشرف، حسام، شادي.

### خدمات Firebase وGroq المطلوبة

أضف المتغيرات من `.env.example` إلى بيئة التطوير وبيئات Vercel المطلوبة. لا تضع مفاتيح الخدمة داخل `VITE_*` أو في المستودع. أضف `FIREBASE_SERVICE_ACCOUNT_JSON` من حساب خدمة محدود الصلاحية إلى الخادم فقط، ويحتاج الحساب صلاحية القراءة والكتابة في Realtime Database. خزّن `CALL_AUTH_RATE_LIMIT_SECRET` كسر عشوائي قوي لا يقل عن 32 حرفًا، ولا تضع قيمته في المستودع.

1. فعّل Firebase Authentication كخدمة، وفعّل Anonymous Authentication لشاشة العرض؛ لا تحتاج تفعيل دخول البريد وكلمة المرور.
2. ضع UIDs الثابتة للمسؤولين الثلاثة في `CALL_ADMIN_UIDS_JSON` واربطها على الترتيب بالأدوار `general_manager` و`business_development_manager` و`deputy_general_manager`.
3. انسخ إعدادات Firebase وحساب الخدمة إلى `.env.local` (المستثنى من Git)، ثم نفّذ `npm run setup:control-passwords` من نافذة طرفية تفاعلية. يطلب الأمر كلمة مرور مختلفة لكل مسؤول بإدخال مخفي، ثم يحفظ تجزئات `scrypt` ذات Salt عشوائي 16 بايت فقط في المسار الخاص `/controlAuth/admins` في Realtime Database. لا يطبع كلمات المرور أو التجزئات، ويرفض إعادة التهيئة إذا كانت الحسابات مهيأة مسبقًا.
4. قواعد Realtime Database تمنع قراءة وكتابة العميل لجميع بيانات المسؤولين ومحاولات الدخول؛ تبقى صلاحية حساب الخدمة على الخادم فقط. مخزن المحاولات يستخدم ETag وعمليات مقارنة وتبديل ذرية مشتركة بين نسخ Vercel، ويسمح بخمس محاولات لكل عنوان خلال 15 دقيقة ويزيل السجلات المنتهية تلقائيًا.
5. جلسة المتصفح محفوظة في Cookie موقّع `HttpOnly` و`SameSite=Strict`، ويجدد الخادم رمز Firebase عند الحاجة. تنتهي الجلسة نهائيًا بعد 12 ساعة. تغيير كلمة المرور متاح للمسؤول بعد تسجيل الدخول، ويتطلب كلمة المرور الحالية وكلمة مرور جديدة مختلفة عن حسابات المسؤولين الأخرى. يُرفع رقم الجلسة المحفوظ في قاعدة البيانات؛ كل طلب لاحق يعيد التحقق منه، فتُرفض الرموز القديمة فورًا. زر الخروج يرفع رقم الجلسة أيضًا.
6. أضف `GROQ_API_KEY` إلى بيئة الخادم فقط، وحدد `GROQ_VOICE` إلى `fahad` أو `sultan` أو `abdullah` (الافتراضي `fahad`). لا يحتاج الصوت إلى Firebase Storage أو Supabase أو Vercel Blob أو بطاقة بنكية للتخزين. ملفات بيئة الخادم لا تستخدم بادئة `VITE_`.
7. مفتاح SHA-256 يتضمن النص النهائي بعد توحيد المسافات فقط، والنموذج والصوت وسرعة/معدل العينة وإصدار إعدادات النطق. يفحص مستقبِل الشاشة IndexedDB أولًا، ثم أصل المكتب الثابت `public/audio/calls/<sha256>.wav`، ثم يطلب التوليد من الخادم عند الحاجة. يحفظ الملف المتحقق منه في IndexedDB، ولا يحذف الملفات تلقائيًا؛ تغير النص أو الصوت أو الإصدار ينتج مفتاحًا جديدًا.
8. IndexedDB خاص بكمبيوتر العرض ونفس ملف المتصفح ونفس أصل الموقع. يبقى عبر تحديث الصفحة والنشر على نفس النطاق، لكنه ليس نسخة احتياطية سحابية. يطلب التطبيق `navigator.storage.persist()`؛ المتصفح قد يرفض الطلب. إذا حذفت الصوتيات تُولد عند النداء التالي. مسح جميع بيانات الموقع يمسح هوية Firebase المجهولة أيضًا، ويعيد إنشاءها تلقائيًا عند فتح الصفحة. لا تستخدم التصفح الخاص أو مسح بيانات الموقع عند الإغلاق على جهاز العرض.
9. عند إرسال النداء، تحفظ صياغة الكلام المنقحة وإعداداته كبيانات خاصة مؤقتة في `calls/audioRequests` لمدة عشر دقائق؛ لا توجد أي بايتات WAV في Realtime Database أو Firestore، ولا يصل النص الخاص إلى تغذية الشاشة العامة. تبقى قاعدة البيانات للنداءات والصلاحيات والأقفال الصغيرة فقط. تمنع Web Locks التوليد المتكرر في علامات تبويب نفس المتصفح، ويمنع قفل الخادم التوليد المتزامن. لا توجد إعادة محاولات تلقائية عند فشل Groq، و429 يفعّل فترة تهدئة.
10. افتح `/` على جهاز العرض؛ تتصل الشاشة تلقائيًا وتستقبل النداءات دون اقتران أو رمز. صفحة `/control` هي الواجهة الوحيدة لإرسال النداءات، ويتحقق الخادم من كلمة مرور المسؤول ودوره عند كل إرسال. هوية الشاشة المجهولة تسمح بعرض النداء وتأكيد تشغيله فقط، ولا تمنح صلاحية إدارية. لا يُعلَن بدء الصوت إلا بعد حدث `playing` الفعلي.
11. للاختبار المعزول شغّل `npm run test:groq-speech -- --confirm-provider-calls` وافتح عنوان localhost الذي يطبعه. يسمح الاختبار بطلب Groq واحد فقط، ويختبر حفظ عينة فهد وإعادة فتح IndexedDB وإعادة استخدام الصوت، دون Firebase أو نداءات حقيقية أو تشغيل تلقائي. تحفظ العينة والتقرير في `.audio-test/` المستثنى من Git. بعد موافقة مالك المشروع على الجودة فقط، يمكن توليد أصول المكتب الخمسة عشر باستخدام `npm run warm:call-audio -- --confirm-provider-calls --approve-all-15`. للمراجعة دون أي توليد أو قراءة للمفتاح استخدم `npm run warm:call-audio -- --dry-run`.
12. غيّر `GROQ_SPEECH_CONFIG_VERSION` عند تغيير صياغة النطق أو إعداداته. بيئة Preview تستخدم `FIREBASE_DATA_NAMESPACE=preview` وتغذية منفصلة `preview/calls/public`، بينما الإنتاج يبقى على المسار الأصلي. لا تفعّلها قبل تطبيق قاعدة القراءة المجهولة المقصورة على `preview/calls/public` من `database.rules.json`. الأصول الثابتة علنية؛ لا تضع فيها أسماء اجتماعات متغيرة أو بيانات عملاء. لا تعتمد على ملفات Vercel المؤقتة أو RAM كذاكرة صوتية دائمة.
13. لا تستخدم أي كلمات مرور حقيقية داخل الاختبارات أو ملفات المشروع. لا تنشر إصدارًا قبل ضبط متغيرات Vercel وتشغيل إعداد كلمات المرور فعليًا والتحقق من دخول المسؤولين الثلاثة.

### حدود الخطط المجانية

- لم تُظهر واجهة Vercel API المتاحة خطة الحساب أو تفاصيل فوترة المشروع. إذا كانت الخطة Hobby، فشروطها تقصرها على الاستخدام الشخصي غير التجاري؛ تخزين الصوت محليًا لا يغيّر شرط الاستضافة. لم تُنشأ خدمة Blob ولم تُفعّل فوترة. يلزم حسم أهلية الاستخدام التجاري قبل النشر الرسمي. المراجع: [شروط Vercel](https://vercel.com/legal/terms)، [إرشادات الاستخدام العادل](https://vercel.com/docs/limits/fair-use-guidelines).
- Realtime Database مستقل تمامًا عن Firebase Storage. لم تُفعّل Blaze أو خدمة تخزين Firebase. قبل الاختبار، حافظ على قواعد القراءة الحالية وأضف فقط مسار القراءة المجهولة للنداءات التجريبية؛ لا تسمح بكتابة العميل أو قراءة بيانات المسؤولين.

### سلوك الأمان والتسليم

- قبل أي نداء، يُقرأ جدول Google Sheets مباشرة؛ تعذر التحقق من المصدر يمنع الإرسال.
- عند انشغال الموظف، تظهر كل الاجتماعات الجارية مع البيانات المتاحة فقط. الإلغاء لا ينشئ أي حدث، والتأكيد يعيد فحص الجدول قبل الإرسال.
- نداء المكتب يذكر اسم المسؤول، ونداء الاجتماع يقرأ عنوان الاجتماع بعد حذف رقم التذكرة والروابط. إذا احتوى العنوان على مؤشرات بيانات عميل أو رقم جوال، يستبدل بصياغة عامة. لا تُحفظ صياغة الكلام الخام داخل حدث الشاشة.
- شاشة العرض لا تعرض تفاصيل الاجتماع الداخلية؛ تستقبل اسم الموظف ونوع النداء ومفتاح الصوت فقط، وتطلب الملف عند عدم وجوده محليًا.
- تُحفظ أحداث النداء في Firebase لمدة عشر دقائق، ويمنع معرّف النداء وتخزين الاستلام على شاشة العرض إعادة الصوت بعد التحديث أو إعادة الاتصال.
- المتصفح لا يعلن نجاح الصوت عند إرسال الأمر؛ يعتمد التأكيد على حدث `playing` الفعلي من شاشة العرض.
- لتشغيل الصوت على التلفاز: افتح لوحة العرض على Chrome أو Brave، ووافق مرة واحدة على تفعيل الصوت من داخل الصفحة. إذا كان العرض عبر Cast فاختر مشاركة علامة تبويب Chrome مع صوتها، وتأكد أن صوت التلفاز والمتصفح غير مكتومين.
- استخدم علامة تبويب واحدة لشاشة العرض مفعّلًا صوتها؛ قفل الكاش يمنع تكرار التوليد بين التبويبات، لكنه لا يغني عن اختيار شاشة استقبال صوتي واحدة.

### قائمة التحقق قبل التفعيل

- سجلات المسؤولين الثلاثة وتجزيئات كلمات المرور موجودة في Realtime Database؛ يلزم اختبار بيانات الدخول الحالية في Preview قبل التسليم.
- لم تُضف مفاتيح Groq أو Firebase الحقيقية إلى المستودع، ولا يُفعّل الصوت قبل إعدادها.
- استُخدمت الأسماء الثابتة للدور والموظف فقط؛ لا توجد رسائل أو تسجيلات دخول تجريبية ترسل إلى شاشة الإنتاج.
